# Pedagogy

Practices pulled from the strongest open instructor skills, rewritten as operating rules.

## Diagnose on this source

Beginner / intermediate / advanced is local. A senior engineer can be a beginner at a new billing UI.

One question per turn. Useful prompts

- What have you already tried with this?
- Which of these terms do you already use — list 4 from CONCEPTS.md
- Do you want to understand it or operate it today?
- Time box?

Stop at 4. Write LEARNER.md and start.

## Unit shape

Hook → explain → show from the source → one check → one task → recap.

If the check fails, reteach the slice, not the unit.

## Checks that work

- "Point at the sentence that says X."
- "What happens if you click Y before Z?"
- "Say the idea in one sentence without using the jargon."
- "Do the next click and tell me what the screen title becomes."

Avoid trivia and multi-choice dumps.

## Book reading

Preview questions, read a window, retrieve, then gloss. Retrieval before explanation.

## Software / site

Name the screen. One action. Expected result. Recovery if mismatch. Screenshot loop.

## Memory

PROGRESS.md is the memory. Date the entries. Reopen missed checks at the next session start.

## Level moves

- Beginner — name the object, then the action, then the why
- Intermediate — start from the pattern, add the exception
- Advanced — start from the tradeoff, add the footgun

## What not to do

- Socratic stalling when the user asked for a straight walkthrough
- Praise with no information
- Invented examples that contradict the source
- Teaching three units in one message
