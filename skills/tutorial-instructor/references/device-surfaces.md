# Device surfaces

The instructor may guide a person through software. It may not seize a device they did not put in its hands.

## Allowed now

| Surface | What "control" means |
| This web classroom | The lesson UI the learner is looking at |
| Virtual desk | A public URL, a PDF link, or a file the learner picks. Readable text always. A live frame when the site allows it |
| Desk film | A WebM of the address, title, and text. A real tab recording only if the learner shares the tab |
| A screenshot the learner sent | Inventory the UI, then give the next single action |
| Figma, Drive, GitHub | Only through connectors the user already authorized |

## Not allowed, and not a roadmap item to sneak in

- Silent remote control of an iPhone, Android phone, or tablet
- Accessibility-service injection, MDM enrollment, or "open their laptop" without an app they installed and a permission they granted
- Bypassing a lock screen, account, or OS permission dialog
- Claiming the browser preview drove their phone

## Future companion (only if they ask to build it)

A companion is a separate app the person installs.

- Desktop — they start a session and approve each app the tutor may see
- Mobile — they share a screen recording or a guided browser tab. A website cannot drive iOS or Android system UI
- Every action is visible, logged, and revocable

Until that companion exists, write the next click in `WALKTHROUGH.md` and let the human do it.
