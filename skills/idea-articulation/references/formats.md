# Audience packs and output formats

Pick one format after the idea is clear. Do not mix formats in one dump.

## Elevator pitch (30 seconds)

```
[WHAT] in one sentence.
[WHY] it matters — one metric or pain point.
[HOW] it works — one mechanism.
[PROOF] it is real — one evidence point, or U if unproven.
```

## One-pager

```
## Problem (2 sentences)
## Solution (3 sentences)
## Evidence (bullets with numbers or U)
## Next steps (WHO → WHAT → WHEN)
## Risks
```

## Decision document

```
## Decision needed
## Options table (option, pros, cons, effort, confidence)
## Recommendation
## If we are wrong (rollback)
```

## Status update

```
## Done
## Blocked (what, why, who unblocks)
## Next (WHO → WHAT → WHEN)
## Metrics (target, actual, trend)
```

## Architecture brief

```
## What it does (no jargon)
## How it works (3 bullets or a pin map)
## Why this design (trade-offs)
## Dependencies
## Risks
```

## Audience adaptation

- Directors / buyers — lead with cost, time, risk, ROI. No pin numbers unless asked.
- Engineers / firmware — lead with architecture. Must be implementable.
- Customers / Etsy / DJ — lead with their pain, then the demo.
- Investors — market size and traction only if real numbers exist. Otherwise U.

## Cognitive operation (when writing long-form)

Name the primary operation before drafting.

- Shift — they define it wrong; flip the definition
- Update — they are missing one piece
- Deepen — they know it but it does not land
- Construct — they have no map yet

Work context front-loads the takeaway. Public/newsletter context earns continued attention.
Run a 4pm-Friday test. Tired reader still gets the one takeaway in the first three sentences.
